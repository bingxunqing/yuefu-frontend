# 乐府：基于AI五线谱识别的乐谱即时预览与理解系统

> **Yuefu: An AI-Based System for Instant Preview and Understanding of Musical Scores via Staff Notation Recognition**
>
> 第十九届全国大学生软件创新大赛参赛作品 | 希望之峰小队

---

## 一、项目概述

**乐府**是一款面向音乐学习者的智能乐谱理解工具。用户只需拍摄或导入纸质乐谱、扫描件或照片，系统即可通过AI光学音乐识别（OMR）技术自动将五线谱转化为结构化音乐数据，并即时生成可听音频与可视化演奏演示，实现"即拍即听、所见即所听"。

项目核心定位是满足用户"**听其大略**"的高频需求——在接触一首新乐曲时，快速获得其整体风格、旋律走向与节奏特征，无需漫长的识谱训练或专业演奏能力。

---

## 二、痛点与需求

### 2.1 识谱门槛高

五线谱作为国际通用音乐语言，学习曲线陡峭。音乐初学者往往需要数年训练才能达到流畅视奏水平，面对复杂乐谱时难以快速理解其音乐内涵。

### 2.2 心理预演困难

即使能够识别音符，普通用户也很难在脑中形成完整的音乐效果。正如程序员无法仅凭代码想象页面渲染效果，音乐家也难以一拿到乐谱就在脑中"听"到音乐。

### 2.3 反馈周期过长

传统方式下，用户必须通过实际演奏或借助专业设备才能验证对乐谱的理解。从"看到乐谱"到"听到音乐"的路径漫长且低效。

### 2.4 工具碎片化

现有方案功能分散：识别工具只输出文本，试听软件需要预置曲库，打谱软件操作复杂。用户往往需要组合多款工具才能完成"识别→试听→理解"的完整流程。

---

## 三、核心功能

### 3.1 智能乐谱采集与识别

- 支持**拍照**（调用相机）或**导入图片**（相册选择）两种方式获取乐谱
- 本地图像预处理：二值化、去噪、对比度增强、倾斜校正
- 云端AI识别：基于Legato端到端OMR模型，将乐谱图像转化为结构化数据
- 提供**双模型选择**：
  - **正声**（全精度）：识别精度高，满足专业需求
  - **清商**（半精度量化）：响应极速，适合快速浏览主干结构

### 3.2 即时试听与多音色切换

- 将识别结果实时合成音频，用户无需等待即可聆听
- 支持多种乐器音色：钢琴、电子琴、弦乐等
- 播放控制：暂停、跳转、调速、循环

### 3.3 钢琴瀑布流可视化

- 音符以彩色条块形式从屏幕顶部下落
- 底部虚拟钢琴键盘同步高亮对应琴键
- 音频、动画、键盘反馈三者严格同步
- 帮助用户直观建立"音符→音高→键盘位置"的关联

### 3.4 标准格式导出

- 识别结果可导出为**MusicXML**行业标准格式
- 兼容MuseScore、Finale、Sibelius等主流打谱软件
- 解决"扒谱困难"的核心痛点，实现从纸质乐谱到可编辑数字乐谱的完整闭环

### 3.5 AI音乐编配

- 输入提示词与参数，实时生成音乐
- 支持将OMR识别后的乐谱输入AI模型进行改编
- 提供风格转换、乐器替换、即兴发挥等创作辅助

|  |  Compose)    |  |              |                     |
|  +------+-------+  +------+-------+                     |
+--------+---------------+--------------------------------+
         |               |
         +-------+-------+
                 |
                 v
+---------------------------------------------------------+
|                      后端服务层                          |

+---------------------------------------------------------+
         |
         v
+---------------------------------------------------------+
|                     云函数层(Serverless)                 |
|            阿里云函数计算(FC) + Docker容器               |

### 关键技术选型

| 层级 | 技术 | 用途 |
|------|------|------|
| 前端 | Jetpack Compose / Vue.js | UI框架 |
| 前端 | MidiDriver | MIDI实时交互 |
| 前端 | Room | 本地数据持久化 |
| 后端 | Spring Boot | 服务框架 |
| 后端 | Retrofit | 网络通信 |
| 后端 | Dom4j | XML解析处理 |
| 云函数 | Legato | 端到端OMR识别 |
| 云函数 | Docker | 容器化部署 |
| 音频 | FluidSynth / Timidity++ | MIDI合成 |

### 处理流程

1. **用户输入**：拍照或导入乐谱图像
2. **图像预处理**：本地进行二值化、去噪、倾斜校正
3. **云端识别**：上传至阿里云FC，Legato模型生成ABC记谱
4. **格式转换**：后端将ABC转为MusicXML标准格式
5. **音频合成**：MusicXML解析为MIDI事件，软音源实时渲染
6. **可视化呈现**：音符瀑布流 + 虚拟键盘同步展示

## 五、项目创新点

### 5.1 端到端乐谱理解

突破传统分步pipeline架构的误差累积问题，采用基于Legato的视觉-语言统一建模方法，实现从"乐谱图像->音乐语义序列"的直接映射。通过Transformer自回归解码与Cross-Attention跨模态融合，支持跨行、跨系统的复杂乐谱全局建模。

### 5.2 "识别-试听-可视化-导出"完整闭环

市场上现有产品多集中于单一环节：识别工具缺乏试听与可视化，教学软件曲库封闭、不支持自定义乐谱。乐府打通全流程，让用户无论持有何种形式的乐谱，都能快速获得听觉反馈与可视化预览，并导出可编辑的标准格式文件。

### 5.3 精准场景定位

不同于面向专业音乐人的深度分析工具，乐府聚焦于"**听其大略**"的轻量化需求——快速预览、即时感知、辅助决策。这种差异化定位使产品能够服务于更广泛的大众用户群体，降低音乐学习的入门门槛。

### 5.4 跨模态音乐理解探索

项目验证了"所见即所听"的人机交互范式，将视觉乐谱直接映射为听觉体验。这一探索具有更广泛的技术价值，可延伸至手写乐谱识别、古籍乐谱数字化、音乐教育自动化等领域。

## 六、应用场景与价值

### 6.1 目标用户

- **音乐初学者**：快速建立听觉认知，降低识谱门槛
- **业余学习者**：接触新曲目前快速了解整体风格
- **钢琴教师**：教学中即时演示乐曲，提升效率
- **作曲家/编曲者**：改编前快速参考原曲效果，评估方案

### 6.2 典型场景

| 场景 | 使用方式 |
|------|----------|
| 课前预习 | 拿到新谱先拍照试听，了解整体难度与风格 |
| 教学演示 | 教师即时将纸质教材转化为可听音频 |
| 创作参考 | 将收集的纸质乐谱快速数字化，辅助改编 |
| 乐谱整理 | 将个人收藏的扫描件批量转化为可编辑格式 |

### 6.3 项目价值

- **降低门槛**：无需专业识谱能力，即可获得乐谱的听觉印象
- **提升效率**：将"看到乐谱->理解音乐"的时间从数小时压缩至数分钟
- **填补空白**：市面上尚无同时覆盖"识别-试听-可视化-导出"全流程的工具
- **文化遗产**：为图书馆、博物馆等机构提供乐谱数字化解决方案
- **无障碍应用**：视觉障碍者无法阅读传统五线谱，乐府通过AI将纸质/图片乐谱转化为音频，使视障用户能够独立"阅读"乐谱、感受音乐，打破音乐学习的视觉壁垒，实现音乐教育的普惠与包容
