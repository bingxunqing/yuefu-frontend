# 测试计划

## 测试策略与目标

测试策略：本项目的测试采用分层测试策略（单元测试、功能测试、系统及模型性能测试）。测试重点与难点聚焦于核心的OMR（光学乐谱识别）技术，特别是老旧、泛黄纸质乐谱在复杂光照下的识别率，以及复杂和弦、多声部音符结构解析的准确性。

目标：确保Web端与Android端APP能够稳定顺畅地完成“拍摄/上传→云端识别→XML下发→动态渲染”的全链路闭环。要求核心模型在常规场景下具备高可用性，前端音符瀑布流渲染要求高帧率、低延迟，保证视听同步。

## 测试范围

覆盖前端UI交互（Web端与Android端）、图像本地预处理模块、云端OMR模型接口调用、MusicXML文件生成与解析模块、音符瀑布流及虚拟键盘的可视化渲染与走带控制、以及非法文件的异常拦截。

## 测试环境

**前端平台：**Web端主流浏览器（Chrome/Edge等）、Android移动端设备。

Spring Boot后端运行环境：

* 阿里云ECS
* 4核心
* 4 GB RAM

**后端/模型运行环境（硬件）：**

* 实例类型：fc.gpu.ada.1（Ada系列架构）
* vCPU/内存：8 vCPU / 64 GB RAM
* GPU显存：48 GB
* 算力：119 TFLOPS（清商） / 60 TFLOPS（正声）
* 磁盘存储：10 GB（可动态扩展）
* 单实例并发度：20

**网络环境：** 稳定的宽带/4G/5G网络环境。

## 模型性能测试

为了全面衡量OMR算法的准确性，引入四个核心评估指标。其中，符号错误率（SER，Symbol Error Rate）和字符错误率（CER，Character Error Rate）是基础的微观评估标准。SER主要聚焦于五线谱中独立音乐符号（如音符、休止符、升降记号等）的识别错漏情况，直接反映了模型对核心乐理元素的像素级捕捉能力；CER则侧重于评估乐谱中附带的文本信息（如速度标记、表情术语、指法数字等）的识别精度。这两个指标的数值越低，说明模型在局部细节的还原上越为精准。

除了微观层面的识别，乐谱的整体拓扑逻辑和结构连贯性同样至关重要，为此我们使用了行错误率（LER，Line Error Rate）和归一化树编辑距离（TEDn，Normalized Tree Edit Distance）来进行宏观层面的结构化评估。LER侧重于衡量整行五线谱（或整个声部系统）在序列上的完整性，一旦某一行内出现导致结构崩坏的严重错位或遗漏，该指标就会显著上升。而TEDn专门用于评估模型最终生成的结构化数据（如MusicXML）的逻辑准确度，它通过计算将预测的乐谱语法树转换为真实基准语法树所需的步骤比例，客观地反映了模型在多声部解析以及复杂和弦时空关系重构上的综合理解能力。

### 测试结果综合分析及建议

在本次模型性能评估中，系统针对复杂多变的真实用户上传场景，验证了“高精度”与“极速预览”双轨并行的识别策略。

针对需要精细打谱或专业练习的用户，系统主推的“正声”全精度模型展现了极为稳健的特征提取能力。测试数据显示，在包含光照干扰和角度偏移的复杂样本集中，“正声”模型的符号错误率（SER）控制在10.92%，字符错误率（CER）为8.55%。该模式虽然在云端消耗的算力及时间略长，但最大限度地保证了乐谱细节的准确还原。

针对仅需快速浏览乐谱主干结构或进行即兴视奏的用户，系统提供了基于“清商”半精度量化的极速模型。该模型大幅缩减了推理耗时与显存占用，实现了极速响应。但测试结果也客观显示，“清商”模型在追求速度的同时，对复杂图像特征的宽容度有所下降，其符号错误率（SER）升至29.58%，行错误率（LER）达到了43.60%。

**改进建议：**当前产品架构下，双模型策略极大地丰富了应用场景。但在后续版本迭代中，“清商”模型的识别准确率仍有较大的优化空间。建议在保留其极致速度优势的前提下，引入量化感知训练（QAT）技术或采用知识蒸馏（Knowledge Distillation），引导轻量化模型更好地学习全精度模型对复杂光影的抗干扰能力，从而为选择“极速模式”的用户提供更高可用性的结果反馈。

### 测试经验总结

本次性能测试验证了产品在AI模型部署上采用分层策略的正确性。通过“正声”与“清商”的对比评估，我们明确了在不同业务场景下，用户对“耗时”与“精度”的敏感度是不同的。一份优秀的软件创新作品，不仅要在算法的绝对精度上追求极致，更要懂得通过工程化手段为用户提供灵活的选择。本次测试指明了项目演进的长期基调：以“正声”保障产品的专业下限，持续通过技术攻坚拉升“清商”极速模式的体验上限，最终实现端云协同下的完美交互。
